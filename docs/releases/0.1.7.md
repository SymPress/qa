# QA 0.1.7

`sympress.preparedSql` (WordPress profile) now also checks untyped
`$this->wpdb` properties, and wpdb's own `get_var()`, `get_col()`, `get_row()`
and `get_results()` on any untyped receiver, such as `$db = $GLOBALS['wpdb']`.
Such an alias may use its own `prepare()` and table-name properties. Remaining
gaps are listed in `docs/adoption.md`. **This tightens a security rule in a
patch release: consumers with dynamic SQL on these receivers will see new
findings.** Fix them with `wpdb::prepare()` or a reviewed local ignore.

`sympress.containerInjection` (app profile) no longer reports
`ContainerBuilder` parameters, which compiler passes, DI extensions and bundles
receive by Symfony's contract.

Project discovery only treats an ancestor as the monorepo root when it holds the
package under `packages/` and belongs to the package's owner or root, so a
foreign directory above a checkout can no longer supply the `vendor/bin` tools
or the adoption file.

`doctor` matches gate references in the `qa` script as whole commands:
`@cs:fix` no longer counts as running `cs`.

The adoption schema `docs/qa-adoption.schema.json` now ships in installed
packages. Also included since 0.1.6: Dependabot updates for GitHub Actions pins.
